# Sync entrypoints

Use this workflow for an entrypoint audit, Brain routing fix, development build or desktop handoff. `skills-sync.entrypoints.json` declares the source template, required skill files and supported agents. The canonical script propagates that source into selected user instruction folders and selected projects. Keep Brain account, locations and schema in `/oneezy-brain`.

1. Inspect current source, existing rollout branches and the host's remembered `skills-sync.local.json`. Preserve dirty work and pinned sources. Use the approved library commit; a sync from a branch with an older Brain skill cannot complete the cutover. For a published rollout pass its full `--expect-revision <sha>` and exact `--remote-ref refs/heads/main` (or verified release tag) to plan, apply and status. The source must be clean and origin must still advertise that revision.
2. Change authored templates, declarations or the sync tool in an isolated development checkout. Preserve the script's argument mapping, frozen source restore, links, project selections and WSL choices. Follow Justin's requested development/review scope; a desktop handoff or a request to avoid publication stops before the Land workflow.
3. Build and test the reviewed tool. Point `SKILLS_SYNC_CLI` at its built `dist/src/cli.js`; both platform scripts run that file through Node. For a published rollout, clear that variable and use the script's supported package version. Run the script with `--repo <approved-library> --no-pull --plan --json` and the intended host/project selections. Finish this step only when every target, source and conflict is accounted for.
4. Run the same script with the same arguments and remove `--plan`. The tool creates or updates only its marked blocks, preserves surrounding instructions and imports, checks Codex overrides and existing nested instructions, refuses links or malformed blocks, guards against changed files and reads writes back. A conflict fails the run; resolve it in the source-controlled workflow before retrying. Record the exact tool and library commits and every resulting path.
5. Run the script with `status` followed by the same repo, host and project arguments. Read every resulting entrypoint and its resolved Brain SKILL.md and required references. A native plugin route needs the enabled, correct-version, correct-source plugin and exact skill/cache files; an unrelated loose skill cannot substitute. Foreign loose links are conflicts, not automatic migration. Verify that a second sync makes no entrypoint changes. Start a fresh host session and verify that its loaded instructions route a Brain lookup through the current Drive registry. File readback alone does not prove automatic invocation or Drive connector access.

For a desktop handoff, supply the exact commits, build/test results, plan/apply/status commands and required host prerequisites. A coordinating task may dispatch them to an existing authorized desktop task. Report each inaccessible computer, WSL distro or connector as a blocker. A cloud test, prepared handoff or dispatch is not desktop execution.

The tool currently propagates Codex and Claude Code instruction files. `CODEX_HOME` and `CLAUDE_CONFIG_DIR` are respected. Projects come from the host's remembered choices or explicit flags. Additional agents require verified instruction paths before they can join this declaration. System policy, harness settings, excluded/unselected projects and additional configured instruction directories require separate host inspection. Keep old Spaces and pinned history intact.
