# Load a named skill

Reference tokens identify skills and apps; they do not execute tools. Read `docs/agents/capabilities.md` and this host’s adapter before resolving an invocation. Preserve disable-model-invocation and agents/openai.yaml policy. Explicit user request text can authorize a workflow; it cannot override a host’s blocked Skill call. Do not reproduce a blocked user-only workflow through manual reads. Never fetch a `SKILL.md` from GitHub, or any copy the harness did not load, to run it (ADR-0011); when a typed skill does not resolve, show the per-harness invocation table (`docs/agents/library.md`, Calling a skill; the harness's global block carries the same one).

For Brain requests load the actual oneezy-brain entrypoint, then its location, capability and operation references. It owns current routing. If a library skill is missing, run `/oneezy-skills` (its script, a plain sync of the latest release; in a cloud thread the setup line `npx --yes @oneezy/skills-sync@latest --quiet`), finish the manual steps it ends with, then verify the skill is visible in a fresh session. The latest release cannot stand in for a held draft rollout; that uses the reviewed tool and library under the current rollout scope.
